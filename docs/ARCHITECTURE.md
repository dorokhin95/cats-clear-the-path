# Архитектура проекта (Architecture Document)

> **Запрещается увеличивать технологическую сложность без объективной необходимости. Для решения простой задачи предпочтительно простое решение.**

---

## 1. Технический стек и обоснование

- **Язык программирования:** TypeScript (строгая типизация без `any`).
- **Сборщик:** Vite (быстрый HMR, легковесный build без оверхеда).
- **Отрисовка игрового поля:** HTML5 Canvas (высокая производительность 60 FPS, независимость от DOM-дерева при манипуляциях сотнями частиц и анимациями).
- **Интерфейс пользователя (UI):** Семантический HTML5 + CSS3 (отличная адаптивность, доступность, удобная стилизация, плавные CSS-переходы).
- **Звуковой движок:** WebAudio API (нативный синтез простых эффектов и процедурные звуки без необходимости тяжелых внешних библиотек).

- **Платформенная архитектура:** Единый интерфейс `PlatformService` с тремя независимыми реализациями:
  1. `WebPlatformService` — базовый автономный веб для браузеров и GitHub Pages (дефолтная платформа).
  2. `TelegramPlatformService` — нативный Telegram WebApp (аппаратный BackButton, HapticFeedback, viewport stable height, safe-area).
  3. `YandexPlatformService` — изолированный адаптер для Яндекс Игр (динамическая загрузка SDK, fullscreen/rewarded ads, cloud save fallback).

### Принцип минимализма зависимостей:
В проекте **не используются** тяжелые фреймворки и игровые движки (React, Vue, Angular, PixiJS, Phaser, Three.js). Игра представляет собой казуальную 2D-головоломку на сетке, где Canvas + нативный DOM обеспечивают максимальную скорость запуска, минимальный размер бандла (< 500 КБ) и мгновенный cold start на мобильных устройствах.

## 2. Разделение ответственности: Canvas vs DOM

```
┌──────────────────────────────────────────────────────────┐
│                   HTML/CSS UI Layer                      │
│   (HUD, Модальные окна, Меню, Настройки, Кнопки)        │
├──────────────────────────────────────────────────────────┤
│                  HTML5 Canvas Layer                      │
│   (Игровое поле, Сетка, Котики, Анимации, Частицы)      │
└──────────────────────────────────────────────────────────┘
```

1. **HTML5 Canvas:**
   - Рисует игровое поле, ячейки сетки, тени.
   - Отрисовывает котиков (процедурно через Canvas 2D Context, с адаптивным масштабированием).
   - Анимирует squash & stretch, рывок, отскок и побег котика.
   - Занимается физикой частиц (лапки, конфетти, пыль) с использованием объектного пулинга (object pooling).
   - Обрабатывает тапы/клики по координатам ячеек.
   - **Оптимизация рендеринга и изоляция экранов:** При нахождении пользователя в полноэкранных меню (Главное меню, Выбор глав, Коллекция, Домик, Настройки) холст Canvas скрывается (`display: none` через класс `.hidden`), а цикл отрисовки пропускается, экономя заряд батареи мобильных устройств и полностью исключая визуальное просвечивание поля.

2. **HTML / CSS UI:**
   - Верхняя панель (HUD): номер уровня, жизни (сердечки), кнопка паузы, живой таймер уровня (`⏱ 00:00.0`), полоса затухания комбо с множителем, кнопка подсказки.
   - Полноэкранные непрозрачные экраны (`.ui-screen--opaque`): Splash Screen, Главное меню, Выбор глав и уровней (постранично по 10 уровней в главе), Коллекция скинов, Домик котиков, Окно настроек.
   - Модальные оверлеи: Меню паузы, Экраны победы и поражения.
   - Все кнопки имеют минимальный размер 44×44px и поддержку `env(safe-area-inset-*)`.

## 4. Игровой цикл и рендеринг (Game Loop)

- Игровой цикл построен на `requestAnimationFrame`.
- Все анимации и перемещения рассчитываются строго через `deltaTime`.
- **Оптимизация неактивного Canvas:** Если игрок находится в главном меню или выборе глав, метод `render()` пропускает кадр, снижая энергопотребление до нуля.
- **Device Pixel Ratio (DPR):** Canvas автоматически масштабируется под физическое разрешение экрана устройства с учетом `window.devicePixelRatio`, что гарантирует четкую картинку на Retina и мобильных экранах.

## 5. Управление состоянием и схема данных V2

1. **Игровое состояние (GameState):**
   - Состояние сетки (размер, объекты, координаты).
   - Список котиков и их локальные состояния (`idle`, `squashing`, `escaping`, `bumping`, `escaped`).
   - Оставшиеся жизни (`lives: number`).
   - Текущий счетчик комбо (`comboCount: number`) и таймер затухания комбо (`comboTimerMs: number`, окно 4.5с).
   - Живое время прохождения уровня (`levelElapsedMs: number`, запускается при первом тапе).
   - Флаг победы/поражения.

2. **Прогресс игрока (PlayerProgress V2):**
   - `version: 2`
   - `lastUnlockedLevel: number`
   - `starsPerLevel: Record<number, number>`
   - `recordsPerLevel: Record<number, LevelRecord>` — рекорды по времени (мс), максимальному комбо и лучшему баллу (0–100) для каждого уровня.
   - `coins: number`
   - `unlockedCats: string[]`
   - `selectedCatSkin: string`
   - `settings: UserSettings`
   - `houseProgression: HouseState`

3. **Сохранение и автомиграция:**
   - `SaveService` поддерживает автомиграцию устаревших форматов: профили V1 безболезненно обновляются в V2 с инициализацией дефолтных рекордов по сохраненным звездам.
   - Автоматическая синхронизация при завершении уровня, покупке скина или изменении настроек.

## 6. Адаптивность и мобильный фокус

- **Базовое соотношение сторон:** 9:16 (вертикальная ориентация для смартфонов).
- **Поддержка экранов:** от узких мобильных (360×640) до планшетов и широкоформатных мониторов (16:9, 21:9).
- **Десктопный режим:** центрированный контейнер игры с адаптивными мягкими полями, без растягивания графики.
- **Safe Area:** Использование переменных `env(safe-area-inset-top)` и `env(safe-area-inset-bottom)` в CSS для предотвращения наложения интерфейса на вырезы камер (notch) и системные полосы жестов.

## 7. Жизненный цикл вкладки и авто-пауза

- Отслеживание событий `visibilitychange` и `blur/focus` окна браузера.
- При уходе пользователя со страницы:
  1. Игра автоматически переводится в режим паузы.
  2. Воспроизведение звуков и музыки плавно приостанавливается через `AudioContext.suspend()`.
  3. Тайминги не искажаются при возвращении благодаря расчету через реальный `deltaTime`.
