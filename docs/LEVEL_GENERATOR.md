# Алгоритмы: Решатель и Генератор уровней (Level Solver & Generator)

> **Ключевой принцип:** Сначала создается и тестируется Солвер (`LevelSolver`), и только затем пишется Генератор (`LevelGenerator`). Никогда наоборот.

---

## 1. Решатель уровней (LevelSolver)

### 1.1. Назначение
1. Автоматическая валидация 100% уровней в модульных тестах перед добавлением в игру.
2. Проверка уровней, созданных процедурным генератором.
3. Обеспечение работы подсказки (💡) во время игры: поиск котика, способного выйти прямо сейчас.
4. Оценка сложности головоломки (метрика глубины и числа развилок).

### 1.2. Алгоритм поиска решения и метрики сложности
1. **Сбор доступных ходов:** Пробежаться по всем котикам на поле. Для каждого вызвать `Board.canCatEscape(cat)`.
2. Если список доступных пуст, но котики на поле остались:
   - Ветка зашла в тупик (deadlock).
3. **Рекурсивный перебор (DFS с возвратом):**
   - Выбрать доступного котика.
   - Симулировать его удаление из копии доски (`removeCatFromPuzzle`).
   - Записать шаг в цепочку решения.
   - Повторять шаг 1, пока поле не станет полностью пустым (`isCleared()`).
4. **Выходные данные анализа (`SolverResult`):**
   - `isSolvable: boolean` — решаем ли уровень.
   - `solutionsCount: number` — количество альтернативных путей решения.
   - `solutionPath: number[]` — эталонная последовательность ходов (ID котиков).
   - `initialMovesCount: number` — число вариантов первого хода.
   - `maxDependencyDepth: number` — длина самой длинной цепочки блокировок (A ждет B ждет C...).
   - `forcedPrefixLength: number` — сколько первых ходов подряд имеют ровно 1 возможный выбор.
   - `branchingFactor: number` — среднее число доступных вариантов ходов на шаг решения.

## 2. Генератор уровней (LevelGenerator): Обратное построение

Для исключения нерешаемых раскладок генератор строит уровень **от конца к началу (обратное построение)**:

```
[ Пустая доска ]
       │
       ▼
1. Поместить котика №1 с открытым выходом наружу (он выйдет последним)
       │
       ▼
2. Поместить котика №2, который блокирует путь котику №1, но сам смотрит в свободную сторону
       │
       ▼
3. Поместить котика №3, блокирующего №2...
       │
       ▼
... (повторить N раз до целевого числа котиков)
       │
       ▼
[ Полное поле ]
       │
       ▼
Прогон через LevelSolver.validate(board) и проверку maxInitialMoves
```

### Преимущества обратного построения:
- Гарантированное существование хотя бы одной корректной последовательности ходов.
- Контролируемая глубина зависимостей: регулируя, кого блокирует новый котик, мы точно задаем сложность уровня.
- Нулевой риск генерации «мертвых петель» (deadlocks).

---

## 3. Метрики и классификация сложности

| Сложность | Размер сетки | Число котиков | Глубина цепи | Max Initial Moves |
| :--- | :--- | :--- | :--- | :--- |
| **Easy** | 3×3, 4×4 | 3–5 | 1–2 | 3 |
| **Normal** | 4×4, 5×5 | 6–9 | 3–4 | 2 |
| **Hard** | 5×5, 6×6 | 10–14 | 5–7 | 2 |
| **Expert** | 6×6, 7×7 | 15–20+ | 8+ | 1 |

---

## 4. Фактическая реализация (`LevelGenerator.ts`)

- **Класс:** `LevelGenerator` (`src/game/LevelGenerator.ts`).
- **Детерминированный PRNG:** Использует алгоритм `Mulberry32`, инициализируемый хешем сида `v2:${levelId}`. Любой клиент для одного и того же `levelId` воспроизводит абсолютно идентичную расстановку, скины и направления.
- **Гарантия точного количества котиков:** Генератор принимает расстановку строго при `catsData.length === targetCount`. Возврат уровней с меньшим количеством котиков исключен.
- **Строгое соблюдение `maxInitialMoves`:** Ослабление ограничений полностью удалено. Для `hard` начальная свобода строго `<= 2`, для `expert` строго `<= 1`.
- **Реестр скинов:** Генератор использует только 4 полноценно отрисовываемых скина с готовыми палитрами (`ginger`, `smoky`, `snowball`, `shadow`).
- **Резервный уровень (`createFallbackLevel`):** В случае экстремальных геометрических коллизий детерминированно формирует строгую змейку-цепочку ровно из `targetCount` котиков с единственным открытым фронтиром (`initialMovesCount: 1`).
- **Стресс-верификация:** Пройдено тестирование 1000 уровней подряд (`1000/1000 QA`) на всех сложностях с нулевым числом отказов.
